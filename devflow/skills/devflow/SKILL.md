# devflow v0.2 — 按专业流程做产品，偏离就拉回

规则版本 `DF-2026.10.23-1`（本版新增：发布前必须先过 `launch-check` 上线前检查；阶段 2 / 3 / 5 / 9 加入供应链、密钥、AI 代理权限要求；失败根因 #26–#28）。本文件是流程真源：Claude Code 插件与 Codex 共读同一份；ChatGPT / Claude 客户端用 `client-instructions/`（由 `scripts/build-client-instructions.py` 从本文件的 CLIENT 段生成，禁止手改）。可视化指南：<repo>��发流程指南.html`。

## DF-00 先定模式，再决定要不要动手

| 模式 | 识别 | 允许 |
|---|---|---|
| 讨论 | 「怎么看」「有没有更好的方案」「先聊聊」 | 引用流程给判断，不建 ledger、不写文件 |
| 只读审核 | 「审一下」「review」「看看有没有问题」 | 只读，产出发现，不改 |
| 计划 | 「先出方案」「写个 PRD」 | 写 docs / ledger，不改代码 |
| 执行 | 「做」「实现」「修」「加个」「继续」「按刚才方案做」 | 开工声明 → 改代码 → 验证 |
| 发布 | 「上线」「部署」「发布」「回滚」 | 必须先确认精确目标与环境，先跑 `launch-check`（上线前检查，有 FAIL 即 NO-GO），再走阶段 8 |

关键词只是候选，模式由当前任务状态与用户原话共同判断；「继续」「撤回上一版」沿用已有任务状态。用户说「不走流程」即退出本流程。

## DF-01 开工声明（执行 / 发布模式的第一个动作，5 行）

```
项目 / 本轮范围 / 模式：<目录或名称> / <一句话> / 执行|发布
入口 / 能力 / 风险级别：A 新产品|B1 修复恢复|B2 新增能力|C 小改 / 勾选：服务端□ 登录□ 支付□ 数据库□ 公开交付□ / L1|L2|L3
当前阶段 / 已过门 / 目标门：阶段 N / 门 0|1|2 / 本轮停在门 N
退出条件 / 验证方式：<一句可观察的话> / <单测|集成|E2E|截图|真实依赖>
用户证据或 N/A 理由 / 阻塞：<首批用户来源 + 首条消息日期> 或 N/A（原因）/ <等谁>
```

C 小改与 B1 修复只需前两行 + 退出条件。缺退出条件或（B2 / A 时）缺用户来源，只问这一项。声明写进 `.omc/plans/<name>-todo.md` 顶部；只读审核与讨论模式不建 ledger。

## DF-02 入口分流

| 入口 | 判定 | 进入 |
|---|---|---|
| A 新产品 | 没有代码目录 | 阶段 0 → 2 → 3 → 4 → 5… |
| B1 修复 / 恢复 | 既有项目的 bug、报错、回归、故障 | 按故障范围直接 5 → 6 → 7；生产故障先止血，不查分发证据 |
| B2 新增能力 | 既有项目加功能 | pickup 或 checkpoint → 判断门与能力 → 缺范围或缺分发证据回阶段 2，否则 5 → 6 → 7 |
| C 小改 | 局部、可逆、约 5 分钟 | 5 → 7 机器验证；不含未经验证的生产发布；命中 L3 升级为 B |

非 git 目录：不擅自 `git init`；改前 `ai-file-checkpoint save`；阻碍定位靠 README / TESTING / _review。

## DF-03 能力勾选与风险级别

- 能力勾选：服务端 / 登录 / 支付 / 数据库 / 公开交付。每个阶段只检查勾中的能力，其余 N/A 加理由。自用还是商业目标单独记录，不从架构推断。
- 预设：甲 纯客户端（勾 0 项或仅公开交付）/ 乙 客户端 + License Key（支付，无服务端）/ 丙 有服务端（勾服务端 + 任意）。
- 风险级别按**本次变更**触碰的权限 / 数据 / 资金 / 可恢复性定，与收费和门无关：他人数据的登录与归属校验、扩展权限、删改文件的脚本、生产发布、迁移、资金流 = L3；触及共享模块或他人可见行为 = L2；其余 L1。行数不是判据。

## DF-04 功能阶梯三门（登录与支付是里程碑门，不是默认模块）

- 门 1 自用：零登录零支付。证据 = 项目内 `.omc/usage-log.md` ≥ 3 条（日期 / 原来怎么做 / 现在怎么做 / 省了什么）。headless PASS 不算。
- 门 2 他人可用：证据 = 1 个非本人用户完成核心任务 + 1 条具体反馈。此时才加登录、归属校验、限流、错误边界、法律页占位；涉及真实数据的隔离在试用前做完；域名、OAuth、邮箱等墙钟同时启动。未勾登录的项目跳过登录，不跳用户证据。
- 门 3 付费：证据 = 有人明确说「多少钱我买」（落地页点击只算弱意向）。零后端走路径 A（License Key，先查平台能力表：是否要商户密钥、能否客户端直调、退款如何失效；Creem 验证要密钥，需最小服务端代理），有后端走路径 B（webhook 状态机）。KYC、Terms / Privacy / AUP、billing descriptor 同时启动。

## DF-05 九阶段：结果只有 PASS / REVISE / WAITING / STOP / N/A

|---|---|---|---|

| 1 战略仲裁（旁路，从 3 或 6 调用后返回） | `gpt5pro` / `/strategy`；评估分歧点而非照搬 | 仅当 Spike 后仍有会改变方案的分歧且无法用更便宜的本地验证消除，或命中 L3 | 为仪式感烧 Pro 桶；幻觉共识 |

| 6 审查 | L1 机器验证；L2 加 1 轮隔离审，审核者 = 最后写入者的另一模型族；L3 review-optimizer 跨族二审 + 一票否决，≤ 5 轮 + 新会话终审，5 轮未过记 STOP | 无 P0 / P1 且测试通过 | 同族互审；无限互评；只信报告不抽查代码 |

| 9 复盘 | 原来怎么做 → 本次怎么做 → 是否完成 → 用时 / 质量 / 返工 → 下一轮改动；发布后 24 小时复跑 launch-check 的 A 依赖、C 密钥、H 异常登录三类；`/retro`；写进 memory 与决策跟踪 07 | 记录已落盘；「未改变判断」也合法 | 经验只留在聊天；无新证据仍迭代 |

## DF-06 拉回规则（发现信号立即一行提醒，不等用户问）

格式固定：`【devflow 拉回】<信号> → <该做什么>`。用户说「这次跳过」就跳过，不重复同一条。

| 信号 | 提醒 |
|---|---|
| 门 1 项目里开始写登录 / 支付 | usage-log 还没 3 条，登录 / 支付先不做 |
| 执行模式开工但没有声明或 ledger | 先补声明与 ledger |
| 准备说「完成」 | 先扫 TODO / FIXME / test.skip / .only / 未实现分支 / 未跑的测试；证据的代码摘要与当前 HEAD 不一致视为失效 |
| 只改源码就想汇报 UI 改好了 | Playwright 三视口截图看过再报 |
| mock 通过就想上线 | 真实依赖门没跑不算过 |
| 两个模型一致但没有测试或代码事实 | 幻觉共识，找一条事实 |
| 同一分支两个工具同时在写 | 一支笔，停一个 |
| 发布命令但无精确目标 / 环境 / 凭证 | 先补三项再发；生产、预览、dry-run 分开 |
| 发布命令但没有 launch-check 报告，或报告结论是 NO-GO / WAITING、不对应当前 HEAD、编号不齐 | 先跑 `launch-check`；FAIL 修完重跑，人工必查项问到答复再发 |
| 新增依赖没核来源 / 锁文件没入 git / 令牌出现在日志或 AI 输出 | 按 launch-check B1–B2、A1、C3 处理，密钥已泄漏先吊销轮换 |
| 命中 `references/failures.md` 命令模式 | 按表改命令 |

hook 只能看到它观察到的工具调用（Bash 字符串、文件写入）；`npm run deploy`、MCP、平台 API、push 触发的自动部署它看不到，这些靠本节自律。

## DF-07 完成前自检（全部为是才说「完成」；未跑、失败、明确跳过分别写明，不合并成「完成」）

1. 声明里的退出条件已被可观察证据满足，证据带命令 / 时间 / 代码摘要且与当前代码一致。
2. 改动文件无 TODO / test.skip / .only / 桩。
3. 阶段 2 指定的验证层都跑了并贴结果；没跑的写「未跑 + 原因」。
4. ledger 本批全勾，HANDOFF 已更新（≥ 30 分钟任务）。
5. 若发布：凭证、部署状态、健康检查三者都有，且凭证对应当前产物。
6. 若发布：launch-check 报告对应当前 HEAD，结论为 GO 或 GO-WITH-FIXES（不是 NO-GO / WAITING），59 个编号齐全，每个 WARN 有结论与优化建议，「开放流量前必须关闭的 WARN」已关闭。
